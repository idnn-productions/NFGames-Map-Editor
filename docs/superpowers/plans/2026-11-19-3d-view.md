# 3D View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A 3D view of the same plan in the map editor, where a piece is selected and moved along X, Y and Z, or placed from the palette, as boxes from the kinds' footprints.

**Architecture:** `src/view3d.mjs` exports one self-contained function (maths plus a small WebGL renderer). The server writes its source into `src/editor.html` at a marker, as it already does for `plantEditing`, so the page stays one served file and the maths is tested in Node. The page gets a WebGL canvas under its existing 2D canvas; in 3D the 2D canvas is cleared to transparent and draws markers, names and handles through a 3D projection.

**Tech Stack:** Node >= 20, `node:test`, plain HTML/JS, canvas 2D, raw WebGL 1. No dependencies.

**Spec:** `docs/superpowers/specs/2026-11-19-3d-view-design.md`

## Global Constraints

- No runtime dependency and no new served file or route. The security model in `README.md` is unchanged.
- No change to `layout.json`'s format, `schemas/`, the server's API, config options, `src/check.mjs`, `src/plan.mjs`, `src/project.mjs`.
- The frame everywhere: metres, +X east, +Z south, Y up. A 3D point is `[x, y, z]`. `rot` is degrees about Y; a piece's local point `(lx, lz)` is at `(x + lx*cos + lz*sin, z - lx*sin + lz*cos)`.
- The file's `y` is the height shown and edited. `y` of 0 is written as no `y` key. Numbers written to the plan go through the page's `tidy()` (3 decimals).
- `npm test` and `npm run check:browser` pass at the end of every task. The browser check fails on any console error or warning.
- The top view behaves exactly as before.
- Code style of the repo: dense single-file style, comments say why, British spelling (`colour`, `centre`).
- Work on a branch `3d-view`; commit at the end of each task.

## Review Focus

1. WebGL is unavailable or the context is lost: the 3D button is disabled with a tooltip, `?view=3d` falls back to the top view, nothing throws. (Task 2)
2. A view switch, undo, or Esc in the middle of a drag or while placing: the drag ends cleanly, no half-moved state lands on the undo stack. (Task 3)
3. Degenerate geometry: a mark with no size, an unknown kind, an axis pointing straight at the camera (axis drag has no solution), a ray parallel to the ground. Nothing becomes `NaN` in the plan. (Tasks 1, 3)
4. The Y arrow dragged below the ground stops at 0 and removes the `y` key; a multi-selection keeps its relative heights and none goes below 0. (Task 3)
5. Resizing the window, or a device pixel ratio other than 1, while in 3D: both canvases stay aligned, picking still hits what is drawn. (Task 2)

### Task 1: `view3d.mjs` maths, written into the page

**Files:**
- Create: `src/view3d.mjs`, `test/view3d.test.mjs`
- Modify: `src/server.mjs` (`page()`), `src/editor.html` (one marker line beside the `plantEditing` one), `package.json` (`exports` gains `"./view3d": "./src/view3d.mjs"`)

**Interfaces — Produces** (`export function view3d()` returns this object; the function must be self-contained, with no imports and no closure over module scope, because its `toString()` is what the page runs):

```js
// cam: { target: [x, y, z], yaw, pitch, dist, fov }   degrees; yaw 0 looks north (toward -Z), pitch is above the horizon
camera(cam, aspect)            // -> { eye: [x,y,z], viewProj: Float32Array(16), inv: Float32Array(16) }  column-major, near 0.5, far 2000
project(c, p, W, H)            // c from camera(); p [x,y,z] -> [sx, sy, depth 0..1], or null when behind the eye
ray(c, sx, sy, W, H)           // -> { o: [x,y,z], d: [x,y,z] }  d normalised
rayPlaneY(r, y)                // -> [x, y, z] or null (parallel, or behind the eye)
rayBox(r, box)                 // box { c: [x,y,z] centre, half: [hx,hy,hz], rot } -> distance along the ray, or null
axisDrag(r, origin, axis)      // axis 0|1|2: the coordinate on that axis, through origin, nearest the ray; null when the ray is within 3 degrees of parallel
pieceBoxes(q)                  // q { at: [x,z], rot, y, size: [w,d,h], boxes: [[x,z,w,d]...], s, st, hs }
                               //   -> [{ c, half, rot }] one per entry of boxes; s scales x and z, st stretches x, hs scales height; bottoms at y
hostTop(plan, kinds, at, skip) // at [x,z]; skip: Set of piece ids -> { id, top } or null. The fit check's rule (below)
renderer(canvas)               // Task 2; in this task: returns null
```

`hostTop` is `check.mjs`'s rule, restated: candidates are `[...plan.pieces, ...(plan.marks || [])]` in file order, not in `skip`, with `(p.y || 0) <= 0.5`, `kinds[p.kind]` present and `solid !== false`; the first whose scaled boxes (`scale || kindScale[kind] || 1`, `stretch` on x) contain `at` wins; `top = (kind.deck ?? kind.size[2]) * scale`.

### Task 2: The 3D view drawn, with its camera

**Files:**
- Modify: `src/view3d.mjs` (`renderer`), `src/editor.html`, `scripts/browser-check.mjs`

**Interfaces**
- Consumes: Task 1's `V3`.
- Produces in `view3d()`:
  ```js
  renderer(canvas) // -> null when WebGL 1 is unavailable, else
                   //    { draw(c, scene), resize(wPx, hPx), lost: boolean }
  // scene: { clear: [r,g,b], tris: [{ boxes: [{ c, half, rot }], colour: [r,g,b,a] }], ground: { disc: { c: [x,z], r } | rect: { min, max }, colour },
  //          lines: [{ pts: [[x,y,z]...], colour: [r,g,b,a] }] }
  ```
  Depth test on; per-face flat shading (top 1.0, sides 0.82 and 0.68, by face normal); see-through colours (`a < 1`) drawn last with blending and no depth write. `lost` turns true on `webglcontextlost`.
- Produces in the page:
  - `let mode = 'top'` and `setMode(m)` (`'top' | '3d'`); `cam3 = { target, yaw: 35, pitch: 40, dist, fov: 45 }`; `fit3()`.
  - `p3(pt)` -> `[sx, sy]` or null: a world `[x, y, z]` on the canvas, in CSS pixels.
  - `sceneBoxes()` -> `[{ key, piece, boxes, colour }]`: every piece and mark with its `pieceBoxes`, used for drawing here and picking in Task 3.
  - `window.__map`: `get mode()`, `setMode`, `get cam()`, `toScreen3(pt)` (page coordinates, as `toScreen`).

**What to build**

- Markup: `<canvas id="gl">` before `<canvas id="map">` in `<main>`, same absolute box; `#map` gets `background: transparent` in 3D (a class on `<main>`). Two buttons `#viewTop`, `#view3d` in a small bar at the top left of `<main>`; `#hud` moves right of them.
- `setMode('3d')`: creates the renderer once; when it is null or `lost`, disables `#view3d` with title `This browser has no WebGL: the 3D view needs it.` and stays in the top view. First entry calls `fit3()`: target the map's centre at y 0, `dist` so the ring or bounds fill the view. `?view=3d` calls it after load. **Tab** toggles (not while typing; `preventDefault`).
- `draw()` begins `if (mode === '3d') return draw3();`. `draw3()` builds the scene and draws the 2D layer over it:
  - Ground disc or rectangle `#c9a27a`; clear colour `#8a6a4c`; grid lines every 1, 5 or 10 m by `cam3.dist` (under 40, under 150, else) when `show.grid`.
  - Ring wall: boxes 2 m high, `D.wallThickness / P()` thick, as 72 segments round the ring, leaving out those within `gateWidth / 2` of the gate.
  - Pieces: `pieceBoxes` with `s = drawScale(p)`, `st = p.stretch || 1`, `hs = drawScale(p)`, `at = drawAt(p)`; `y` drawn as `(p.y || 0) * f`, where `f` is `lookK(host.kind) / P()` for the `hostTop` piece under it, else `lookK(p.kind) / P()`. Colour as the top view's (`classOf(cls).colour`, a preset's colour). Kinds with partial `boxes`: the footprint outline as ground lines. Unknown kinds use `info()`'s 2 x 2 x 2 default. A front tick as a ground line.
  - On the 2D layer, through `p3`: the arrival arrow, people, things, doors, round loops and points, hand-placed plants and exclusions at y 0, with the same colours and Show checkboxes as `draw()`; piece ids at the top centre of each piece when `show.labels`; an orange (`COLOUR.sel`) wireframe box round each selected piece; a compass bottom right (the three axes in red, green, blue, and `N`).
  - Rule-made plants and the project's layers are not drawn.
- Camera on `#map`'s existing pointer handlers, branching on `mode`: left drag on empty space orbits (0.4 degrees a pixel; pitch clamped 5..89); right or middle drag pans the target along the ground (y stays 0); wheel zooms toward the ground point under the mouse (`dist` clamped 3..1500); **F** calls `fit3()` in 3D. HUD: `x, y, z` of the ground point under the mouse.
- `resize()` sizes both canvases with the device pixel ratio and calls `renderer.resize`.
- `focusOn(at, zoom)` in 3D sets `cam3.target` to `[at[0], 0, at[1]]`, so clicking a problem still shows it.

### Task 3: Selecting and moving in 3D

**Files:**
- Modify: `src/editor.html`, `scripts/browser-check.mjs`

**Interfaces**
- Consumes: `V3`, `sceneBoxes()`, `p3()`, the page's `handle()`, `select()`, `snapshot()`, `snap()`, `tidy()`, `changed()`, `norm()`.
- Produces in the page:
  - `pick3(sx, sy)` -> `{ key, movable, piece? }` or null: markers first (within their top-view pixel radius of their projected point), then the nearest `rayBox` hit over `sceneBoxes()`.
  - `gizmo()` -> `{ at: [x,y,z], x: [sx,sy], y: [sx,sy] | null, z: [sx,sy], ring: [[sx,sy]...] | null }` or null: for the lead of the selection (the key clicked last). Arrow tips 70 px from the origin on screen. `y` and `ring` only when the lead is a piece.
  - `liftSelected(dy)`: adds `dy` to every selected piece's `y`, none below 0, 0 written as no key; one undo step.
  - `window.__map.gizmo()` (page coordinates) and `window.__map.liftSelected`.

**What to build**

- Pointer down in 3D, left button, in this order: an arrow tip or shaft within 8 px starts `drag = { axis: 0|1|2, ... }`; the ring within 6 px starts `drag = { turn }`; `pick3` hit: Shift or Ctrl toggles it in the selection, otherwise selects it (unless already selected) and starts `drag = { slide }`; nothing hit: clears the selection unless Ctrl, and orbits.
- Axis drag: `V3.axisDrag(ray, origin, axis)` against its value at pointer down gives a delta; the lead lands on `snap()`, the rest keep their offsets. X and Z set `at` through `handle(key).set`. Y applies to pieces only, clamps at 0, and catches: with `top = V3.hostTop(plan, kindsInfo, lead.at, selectedIds)`, when `|y - top| <= 0.3` then `y = top`. `axisDrag` returning null leaves things where they are.
- Slide: `rayPlaneY(ray, lead's drawn y)` gives x and z; same snapping and offsets as the top view's move, including the `attach` factor.
- Turn: angle of the ground hit about the piece's centre, 15 degree steps, Alt for 1, as the top view's handle.
- Every drag keeps `before = snapshot()` and pushes it only on pointer up when something moved, as the top view does. `setMode`, Esc and `undo()` during a drag cancel it by restoring `before`.
- Drawing (2D layer, last): arrows X `#ff5a4d`, Y `#6fdc5a`, Z `#5aa2ff` with heads, the ring in `COLOUR.sel`, the hovered handle brighter; cursor `grab` over a handle, `move` over a pickable thing.
- Keys: **Page Up / Page Down** call `liftSelected(+-snapStep())` (Shift: 1 m) in both views. In 3D the arrow keys nudge along the plan axis nearest the screen direction, from `cam3.yaw` rounded to 90 degrees.
- Shift drag in 3D does not box select: it orbits.
- The Keys text in the left column and the multi-selection hint mention the 3D handles and Page Up / Page Down.
